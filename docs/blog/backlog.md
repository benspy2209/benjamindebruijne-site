# Backlog du blog

Une file par rubrique (voir GUIDE §1 et §9). Chaque routine prend le premier sujet de SA file. Un sujet = une ligne : angle, 2-3 points à couvrir, sources à ouvrir.

## À écrire — gxp
1. **DT SME : à quoi sert ce rôle et pourquoi il manque sur beaucoup de sites** — angle : le traducteur entre Labs/Production/Qualité et IT ; couvrir : 4 responsabilités, à quoi on le reconnaît, quand le créer, ce qu'il n'est pas (ni PM, ni architecte) ; pas de source réglementaire nécessaire, rester descriptif, ne nommer aucun site.
2. **IT/OT : les cinq questions qu'un responsable Qualité doit poser à l'IT** — angle : la convergence IT/OT crée des risques que la Qualité ne voit pas ; couvrir : inventaire, segmentation, accès privilégiés, intégrité des données des automates, plan de continuité ; sources : ISA/IEC 62443 (vue d'ensemble), GAMP 5, annexe 11.
3. **La matrice de traçabilité qui tient en inspection** — angle : l'outil le plus sous-estimé du dossier de validation ; couvrir : URS → FS/DCS → tests, ce qu'un inspecteur y cherche, les 4 erreurs classiques (exigences non testables, tests orphelins, versions divergentes, mise à jour oubliée au change control), un gabarit minimal ; sources : GAMP 5, annexe 11 §4, Part 11.
4. **Intégrité des données en 2026 : ALCOA+ au-delà du slogan** — angle : appliquer chaque lettre à un système réel ; sources : PIC/S PI 041, MHRA GxP Data Integrity guidance 2018, annexe 11.
5. **Revue périodique d'un système validé : la faire sans y passer une semaine** — angle : checklist proportionnée au risque ; sources : GAMP 5, annexe 11 §11.
6. **Annexe 11 : ce que la révision en cours change, et ce qui est déjà acquis** — angle : séparer ce qui est publié de ce qui est en consultation ; couvrir : état exact de la révision de l'annexe 11 EudraLex vol. 4 (vérifier sur ec.europa.eu / EudraLex la date et le statut : projet soumis à consultation ou texte adopté), les thèmes annoncés (cloud, IA, data integrity, fournisseurs), ce que ça implique pour un plan de validation dès maintenant ; sources : Commission européenne / EudraLex, EMA. Ne rien affirmer comme adopté sans source datée.
7. **Revue des pistes d'audit : qui, quoi, à quelle fréquence** — angle : l'exigence que tout le monde cite et peu de sites appliquent ; couvrir : ce que disent annexe 11 §9 et 21 CFR Part 11.10(e), proportionner la fréquence au risque, quoi chercher (suppressions, modifications hors procédure, comptes génériques), comment documenter la revue ; sources : annexe 11, 21 CFR Part 11, PIC/S PI 041, MHRA data integrity 2018.
8. **Qualifier un éditeur SaaS en GxP : les dix questions à poser** — angle : le cloud n'enlève pas la responsabilité du titulaire ; couvrir : évaluation fournisseur selon GAMP 5 (annexe M2), hébergement et localisation des données, gestion des versions imposées, pistes d'audit, sauvegardes/restauration, sous-traitants, accord qualité, audit documentaire vs sur site ; sources : ISPE GAMP 5, ISPE GAMP Good Practice Guide IT Infrastructure Control and Compliance, annexe 11 §3.
9. **Change control sur un système validé : rester validé sans tout re-valider** — angle : classer avant d'agir ; couvrir : classification des changements (mineur/majeur/urgence), évaluation d'impact (GxP, données, interfaces), effort de re-test proportionné, mise à jour de la matrice de traçabilité et de la documentation, revue périodique comme filet ; sources : GAMP 5, annexe 11 §10, 21 CFR 11.10(k).

## À écrire — automatisation
1. **Facturation électronique obligatoire en Belgique : ce qui change vraiment pour une PME** — angle : séparer l'obligation de la panique ; couvrir : qui est concerné et depuis quand (vérifier sur finances.belgium.be / efacture.belgium.be la date et le périmètre B2B), ce qu'est Peppol (réseau, point d'accès, format), ce que ça ne change pas (le processus devis → facture → paiement), les 4 questions à poser à son logiciel ; sources : SPF Finances, BOSA, OpenPeppol. Ne rien affirmer sans la source datée.
2. **Le reporting du lundi : de trois heures d'Excel à un mail automatique** — angle : un tableau de bord utile tient en 5 chiffres ; couvrir : choisir les 5 chiffres, d'où ils viennent (compta, CRM, site), assembler sans ressaisie, envoyer à heure fixe, les pièges (chiffre faux qui circule, indicateur que personne ne lit) ; sources : documentation officielle des outils décrits, aucune statistique inventée.
3. **Relancer ses prospects par mail sans finir en spam** — angle : la relance est un processus, pas un coup de pression ; couvrir : base légale et consentement B2B (APD, RGPD), désinscription, cadence J+3/J+10/J+30, délivrabilité (SPF, DKIM, DMARC), ce qu'on mesure vraiment (réponses, pas ouvertures) ; sources : autoriteprotectiondonnees.be, EUR-Lex RGPD, documentation officielle DMARC (dmarc.org) ou des fournisseurs.
4. **Les cinq tâches à automatiser en premier dans une PME, et les trois à ne jamais automatiser** — angle : critère = répétitive, à règles claires, sans jugement ; couvrir : la grille de tri (fréquence, règles, coût d'une erreur), 5 exemples concrets, 3 contre-exemples (litige client, recrutement, décision de prix), par où commencer ; sans source réglementaire, rester descriptif.
5. **Boîte mail partagée : trier et router avec un LLM, et ses limites** — angle : l'IA classe, l'humain répond ; couvrir : catégories simples, routage vers la bonne personne, brouillon de réponse jamais envoyé automatiquement, données envoyées au modèle (RGPD), mesure du taux d'erreur ; sources : APD/CNIL sur l'usage des assistants IA, documentation officielle des outils décrits.

## À écrire — ia
1. **AI Act : former ses équipes à l'IA est déjà une obligation** — angle : l'article 4 s'applique depuis février 2025 (vérifier la date exacte sur eur-lex.europa.eu / digital-strategy.ec.europa.eu) ; couvrir : qui est concerné, ce que « maîtrise de l'IA » veut dire, un programme de formation en 3 niveaux, la trace à garder, le calendrier des autres obligations ; sources : EUR-Lex règlement (UE) 2024/1689, Commission européenne.
2. **Un assistant interne sur vos documents : ce qui marche, ce qui déçoit** — angle : la qualité des réponses dépend des documents, pas du modèle ; couvrir : quels documents (procédures, FAQ, contrats types), nettoyage et droits d'accès, évaluation par un jeu de 30 questions, humain dans la boucle, coût réel ; sources : APD/CNIL, documentation officielle des outils décrits.
3. **Votre entreprise est-elle citée par les IA ? Méthode de mesure en une heure** — angle : mesurer avant d'optimiser ; couvrir : 10 questions qu'un client poserait, 3 assistants, grille de notation (cité / non cité / concurrent cité), lecture des résultats, ce qui influence (site clair, pages de réponse, avis) ; retours d'expérience des mesures faites sur des secteurs belges (chiffres anonymisés déjà publiés par Ben), sans nommer de société.
4. **Ce que l'IA coûte vraiment à une PME : licences, temps, erreurs** — angle : le coût caché est le contrôle ; couvrir : licences par siège, temps de mise en place, temps de relecture, coût d'une erreur, mesure sur 3 mois, quand arrêter ; sans statistique externe, grille de calcul uniquement.
5. **Les erreurs typiques d'un LLM en entreprise, et comment les attraper** — angle : connaître les pannes pour les encadrer ; couvrir : invention de faits, chiffres déplacés, mauvaise langue, instructions ignorées, dérive dans le temps ; pour chacune : le test qui la détecte ; sources : documentation officielle des fournisseurs sur les limites, AI Act pour les obligations de transparence.
